# Reteach Checkpoint Design Principles

## North Star

Reteach Checkpoint is not a collection of forms.

It is a teacher workspace that guides one instructional decision at a time.

Every screen should reduce cognitive load, highlight the current task, and quietly move completed decisions out of the way.

---

# 1. Design for Workflows, Not Forms

Never expose every field equally.

Every page should have a clear beginning, middle, and end.

Example:

```
Select Student
->
Choose Situation
->
Write the Reteach
->
Serve
```

The interface should naturally pull the teacher from one step to the next.

---

# 2. Progressive Disclosure

Completed decisions should become summaries.

Do not leave completed controls open forever.

Examples:

* Student search becomes a compact student header.
* Situation selectors become a small editable summary.
* History remains visible but secondary.

The page should become quieter as certainty increases.

---

# 3. One Primary Task Per Screen

Every page should answer:

> What is the teacher trying to accomplish right now?

Everything that does not directly support that task should become supporting context.

Example:

Primary task:

* Write the reteach.

Supporting context:

* Student
* Situation
* Previous reteaches

---

# 4. Action Lives on the Left

The left side is always the workspace.

It is where teachers think, write, edit, and make decisions.

The left column should be calm, spacious, and distraction-free.

---

# 5. Context Lives on the Right

The right side is never another form.

It exists to answer:

> What do I need to know before making this decision?

Examples:

* Student Snapshot
* Progress
* Recent history
* Pending work
* Related information

The right column informs.

The left column acts.

---

# 6. White Space is Functional

Empty space is not wasted space.

Writing requires breathing room.

Do not fill empty areas simply because they exist.

White space should pull attention toward the teacher's current task.

---

# 7. Color Has Meaning

Never add color for decoration.

Each color communicates state.

Blue

* Navigation
* Primary actions
* Current workflow

Green / Amber / Red

* Student operational status
* Progress
* Attention level

Neutral Gray

* Supporting setup
* Secondary information

White

* Thinking
* Writing
* Creation

If a color does not communicate meaning, remove it.

---

# 8. Typography Creates Hierarchy

Use typography before adding more boxes.

The page should naturally answer:

1. What am I doing?
2. Who am I working with?
3. What decision comes next?

Avoid unnecessary headings.

Every heading should earn its place.

---

# 9. Collapse Complexity

The interface should become simpler as work progresses.

The user should feel momentum.

Never punish progress by leaving every control visible.

Completed work becomes summaries.

Current work stays editable.

---

# 10. Metadata Should Whisper

Administrative information should never compete with instructional decisions.

Examples:

Assigned by...
Date
Grade
HR

These support the work.

They are not the work.

---

# 11. Build Calm Software

Teachers are already overloaded.

The interface should reduce urgency, not increase it.

Avoid:

* flashing colors
* warning-heavy language
* visual clutter
* unnecessary borders
* competing focal points

Prefer calm confidence.

---

# 12. Personality Comes From Behavior

Do not chase personality through decoration.

Personality comes from interaction.

Examples:

* Student locks in.
* Situation collapses.
* History remains available.
* Writing becomes the focus.

The interface should feel thoughtful because it behaves thoughtfully.

---

# 13. Respect the Teacher

Do not assume teachers are entering data.

Assume they are making professional instructional decisions.

The software should feel like an assistant, not a compliance tool.

Every screen should communicate:

"I'll help you think through this."

---

# 14. Consistency Over Novelty

If a pattern works well, repeat it.

Examples:

* Left = workspace
* Right = snapshot
* Progressive summaries
* Colored status indicators
* Calm writing surfaces

Users should learn the language of the application once.

Every new page should speak that same language.

---

# Final Design Test

Before shipping any page, ask:

* Is there one obvious task?
* Does the eye know where to start?
* Does the interface become quieter as decisions are made?
* Does color communicate meaning?
* Could anything disappear without hurting understanding?
* Does this feel like helping a teacher rather than collecting data?

If the answer is yes, the page is probably moving in the right direction.
